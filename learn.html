How does an OS actually work?

Your computer does a lot more than open apps and display windows. Here's a look at what happens underneath it all.

So... what is an operating system?

An operating system is the software that manages a computer and provides a way for other software to use its hardware.

Windows, macOS, and Linux are all operating systems. They provide things like file systems, networking, device support, memory management, and ways for programs to run.

When you open a browser, save a file, connect a USB device, or connect to Wi-Fi, your operating system is doing a lot of work behind the scenes.

Brack OS is our attempt to build those foundations ourselves.

What happens when you turn on a computer?

Starting a computer is more complicated than it looks. Before you see a desktop, several layers of software have already done their job.

1. Firmware

When the computer starts, firmware such as UEFI or older BIOS initializes the hardware and begins the boot process.

2. Bootloader

The bootloader locates the operating system and loads the kernel into memory.

3. Kernel

The kernel takes control and begins managing the processor, memory, hardware, and other core parts of the system.

4. Userspace

Programs and services can then run on top of the kernel, eventually providing the environment users interact with.

What's a kernel?

The kernel is the core of an operating system. It operates at a privileged level and provides the foundation that the rest of the system relies on.

A kernel has to deal with hardware and resources that applications normally cannot access directly.

CPU

The kernel manages processor time and provides the foundations for running multiple processes.

Memory

The kernel keeps track of memory and controls how it is allocated and accessed.

Devices

Drivers allow the operating system to communicate with hardware such as keyboards, storage devices, displays, and network adapters.

Processes

The kernel provides the mechanisms needed to start programs, manage them, and control the resources they use.

What's a driver?

A driver is software that allows an operating system to communicate with a particular piece of hardware.

Different hardware works in different ways. A network adapter, graphics card, keyboard, and storage controller all have different interfaces that software needs to understand.

This is one reason building an operating system takes so much work. Getting the kernel to boot is only the beginning. The system also needs drivers before it can interact with a wide range of hardware.

Brack OS right now

Hardware support is still being developed. Networking in particular is not currently functional, as Ethernet driver development has only recently begun.

What is userspace?

Userspace is the part of the operating system where normal programs run. Unlike the kernel, userspace programs generally don't have unrestricted access to the hardware.

A command-line shell, text editor, system utilities, and eventually graphical applications can all live in userspace.

Brack OS is currently focused heavily on the kernel. As the project progresses, more functionality will move into userspace.

Why build a kernel from scratch?

There are already plenty of excellent operating systems. So why make another one?

Because building an operating system is an excellent way to understand how computers actually work.

Instead of starting with an existing operating system and modifying it, Brack OS allows the team to work directly on the foundations. Every part of the system presents another problem to solve and another opportunity to learn.

It also means that the team gets to decide how the system develops rather than simply inheriting the design decisions of another OS.

What are architectures?

A processor architecture defines the instruction set and other fundamental rules that software uses to communicate with a CPU.

Operating systems are closely tied to the architecture they run on. Code written for one architecture cannot necessarily run directly on another.

x64

The current primary development target for Brack OS and the main architecture being worked on right now.

x86

The older 32-bit member of the x86 processor family. Planned as a future Brack OS target.

ARM64

A modern 64-bit ARM architecture used by many newer computers, phones, tablets, and embedded systems.

ARM32

A 32-bit ARM architecture used by many older and smaller systems.

16-bit

An experimental target intended primarily for exploration, experimentation, and learning.

RISC-V

An open instruction-set architecture that may be considered for Brack OS in the future.

Why isn't everything working yet?

Because operating systems are complicated.

Getting a kernel to start is only one of the first steps. The system still needs reliable memory management, hardware drivers, storage, networking, userspace programs, and eventually a graphical environment.

Brack OS is still an experimental project. Some commands and features are incomplete or non-functional, and that is expected at this stage of development.

The goal is to build the foundations correctly rather than rush toward a finished-looking desktop.

Where does Brack OS go from here?

The immediate focus is the x64 kernel. From there, development can expand into additional hardware support, userspace, and eventually a graphical environment.

Other processor architectures are also part of the long-term plan, although they will come after the current foundations are further developed.
