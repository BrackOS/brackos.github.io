Technical Documentation

BrackOS x64

A look under the hood at the boot process, CPU setup, memory, display, keyboard, and kernel structure.

Boot process

BrackOS x64 is loaded by GRUB 2 using the Multiboot2 protocol. GRUB starts the kernel in 32-bit protected mode. From there, BrackOS performs the transition into 64-bit long mode itself.

  1. GRUB loads the BrackOS kernel.
  2. The _start entry point is reached.
  3. A temporary 32-bit stack is established.
  4. The Multiboot2 information pointer is preserved.
  5. Paging structures are created.
  6. PAE is enabled.
  7. Long mode is enabled through the EFER MSR.
  8. Paging is enabled.
  9. A 64-bit GDT is loaded.
  10. The kernel performs a far jump into 64-bit code.
  11. A 64-bit stack is established.
  12. kernel_main() is called.

The kernel uses a Multiboot2 header and a GRUB configuration with automatic graphics-mode detection. The boot configuration supports both BIOS and UEFI systems.

CPU

x86-64 Long Mode

After startup, the kernel runs in 64-bit long mode using the AMD64/Intel EM64T instruction environment.

Paging

2 MiB Pages

Paging is enabled using a PML4, PDPT, and page directory. The current mapping identity-maps the first 2 MiB of physical memory.

GDT

64-bit Segmentation

A small GDT provides a null descriptor, a 64-bit code descriptor, and a data descriptor.

Interrupts

Not implemented

The current kernel does not initialize an IDT, enable interrupts, or provide hardware IRQ handlers.

Memory

The kernel is linked to begin at 0x100000, or 1 MiB. Its linker script aligns the major sections to 4 KiB boundaries. 

0x00000000
     │
     │ Reserved / boot memory
     │
0x00100000  ← Kernel base
     │
     │ Kernel sections
     │ .text
     │ .rodata
     │ .data
     │ .bss
     │
     ▼

0x000B8000  ← VGA text buffer

A fixed 16 KiB stack is allocated in the .bss section. There is currently no heap, allocator, or dynamic memory management.

Paging uses 2 MiB pages with identity mapping. This means that, within the currently mapped region, virtual and physical addresses are the same.

The current page tables cover only the first 2 MiB, so this should not be confused with a complete virtual-memory subsystem.

Stack

Fixed-size 16 KiB stack allocated in .bss.

Heap

No heap or dynamic memory allocator is currently implemented.

Memory protection

Paging is enabled, but the current mappings are writable kernel mappings without user/kernel privilege separation.

Exceptions

No exception handlers are currently installed.

VGA display

BrackOS uses the traditional VGA text buffer at 0xB8000. The display provides an 80-by-25 text grid with colored characters. 

Width:       80 characters
Height:      25 lines
Cells:       2000
Foreground:  16 colors
Background:  8 colors
Buffer:      0xB8000

Each display cell contains a character and an attribute byte. The kernel provides functions for printing characters and strings, clearing the screen, scrolling, changing colors, and handling backspace.

Normal text is gray on black. The boot message uses bright white, the shell prompt is green, and unknown command errors are displayed in red.

Input

PS/2 keyboard

Keyboard input is handled by polling the PS/2 controller rather than using interrupts. 

Data port:    0x60
Status port:  0x64
Scancode set: 1

The driver translates scancodes into characters and supports left and right Shift keys, allowing uppercase letters and shifted symbols.

The polling loop uses the x86 pause instruction while waiting for input. Ctrl and Alt modifiers are not currently implemented.

Kernel structure

boot.s

Multiboot2 header, kernel entry point, paging setup, GDT setup, and the transition from 32-bit protected mode to 64-bit long mode.

kernel.c

Main kernel entry, shell loop, command parsing, line input, and string utilities.

vga.c / vga.h

VGA text output, colors, screen clearing, scrolling, cursor handling, and backspace.

keyboard.c / keyboard.h

PS/2 keyboard polling and scancode-to-ASCII translation.

io.h

Low-level I/O helpers for port and MSR access.

linker.ld

Defines the kernel entry point, load address, section layout, and alignment.

grub.cfg

GRUB boot configuration and Multiboot2 kernel loading.

Current state

A small kernel with a lot of room to grow.

BrackOS x64 currently provides the foundations needed to boot a 64-bit kernel, display text, receive keyboard input, and interact with a simple shell.

Interrupts, exception handling, filesystems, networking, multitasking, dynamic memory, USB, and other larger OS subsystems remain outside the current implementation.
