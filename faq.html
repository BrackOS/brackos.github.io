Questions & answers

Frequently Asked Questions

New to operating systems? Curious about what we're building? Here's the stuff you probably want to know before diving in.

What is Brack OS?

Brack OS is an open-source operating system being built from the ground up, including our own custom kernel.

Right now, the project is focused on the foundations of the operating system rather than a graphical desktop environment.

Is Brack OS ready to use?

Not yet. Brack OS is still in active development and does not currently have a public release that we consider ready for everyday use.

When a Canary build becomes available, we'll make it clear on the website and provide instructions for trying it safely.

Will Brack OS replace Windows or macOS?

That's a very long-term question. Our immediate goal isn't to replace anything. We're building Brack OS to learn, experiment, and see how far we can take a completely custom operating system.

If it eventually becomes something you'd actually want to use every day, that's a pretty nice bonus.

Do I need to be a programmer to use Brack OS?

No. Once Brack OS has a usable release, our goal is for people to be able to try it without needing to understand kernel development.

The project is currently command-line based, though, so learning a few basic commands will be useful.

What is a kernel?

The kernel is the core part of an operating system. It is responsible for things such as managing memory, talking to hardware, handling processes, and providing the foundation that other software runs on.

In simple terms: it's the part of the operating system that sits between your software and the hardware.

Why are you writing your own kernel?

Because we wanted to understand how operating systems actually work.

Using an existing kernel would let us build an operating system much faster, but writing our own lets us learn about the foundations directly.

What hardware does Brack OS support?

Our current development focus is x64. ARM64, x86, and ARM32 are planned targets, with other architectures potentially being explored later.

Hardware support is one of the harder parts of operating system development, so compatibility will grow over time.

Will Brack OS have a graphical interface?

Yes, that's the long-term goal.

We're starting with the lower-level parts of the operating system. Once the kernel, drivers, and userspace have developed far enough, we'd like to build a GUI on top of them.

Why is Brack OS command-line based?

Because a graphical interface is a lot more work than it might look from the outside.

A CLI lets us work on the actual operating system underneath without having to build an entire desktop environment first.

Is Brack OS open source?

Yes. The source code is publicly available on GitHub.

You can follow development, inspect the code, experiment with it, and eventually contribute to the project.

Can I contribute if I don't know C or assembly?

Absolutely. Code isn't the only way to help.

Testing, documentation, website development, bug reports, ideas, and simply getting the project in front of people who might be interested can all be useful.

Where can I see what we're working on?

Check out the Brack OS roadmap for our current plans and priorities.

You can also follow the source code and development activity on GitHub.

When will Brack OS be finished?

We don't know. Operating system development is complicated, and we're building this project in our spare time.

We'll publish our best estimates on the roadmap, but they're estimates rather than promises.

Can I install Brack OS on my main computer?

Not yet, and we wouldn't recommend replacing your existing operating system with an experimental build when releases do begin.

Early builds will be much better suited to testing environments, virtual machines, or spare hardware.

What does "Canary" mean?

A Canary build is an early release intended for testing and experimentation. It may contain bugs, missing features, or hardware compatibility problems.

In other words: it's for people who want to see what we're building before everything is polished.
